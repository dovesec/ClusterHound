# ClusterHound - Custom Cypher Queries

These queries are designed for use with [BloodHound CE](https://github.com/SpecterOps/BloodHound) after ingesting ClusterHound data. Import `customqueries.json` via the import_queries.py script in the repo to see them in BloodHound, or run them directly in the Cypher query box.

| Name | Query | Description |
| ---- | ----- | ----------- |
| All Nodes of a Specific Type | `MATCH p=(n:CH_Pod) RETURN p` | Enumerate all nodes of a given type. Replace `CH_Pod` with any node type before running. |
| All Edges of a Specific Type | `MATCH p=(a:CH)-[:CH_canExec]->(b:CH) RETURN p` | View all edges of a given type across the graph. Replace `CH_canExec` with any edge type before running. |
| All Edges from a Specific Object | `MATCH p=(n:CH {objectid: 'NAMESPACE/KIND/NAME'})-[r]->(m:CH) RETURN p` | Explore all outbound relationships from a known object. Replace the `objectid` placeholder with the target object's identifier. |
| Specific Edge Type from a Specific Object | `MATCH p=(n:CH {objectid: 'NAMESPACE/KIND/NAME'})-[:CH_canExec]->(m:CH) RETURN p` | Inspect a specific relationship from a known object. Replace both the `objectid` and edge type before running. |
| Identities with Full Cluster Access | `MATCH p=(n:CH)-[:CH_fullAccess]->(c:CH_Cluster) RETURN p` | Identifies identities holding wildcard RBAC permissions granting unrestricted cluster-wide access. Highest severity finding. |
| Identities with Full Namespace Access | `MATCH p=(n:CH)-[:CH_fullAccess]->(ns:CH_Namespace) RETURN p` | Identifies identities holding wildcard RBAC permissions scoped to a specific namespace. All resources within that namespace are accessible. |
| Nodes Proxy RCE | `MATCH p=(n:CH_Identity)-[:CH_nodesProxyRCE]->(c:CH_Cluster) RETURN p` | Identifies identities with `nodes/proxy` GET permission, enabling proxied requests to the Kubelet API and RCE on any node. |
| Unauthenticated API and Kubelet Access | `MATCH p=(e:CH_ExternalActor)-[r:CH_unauthAPIAccess\|CH_unauthKubeletAccess]->(n:CH) RETURN p` | Surfaces unauthenticated exposure of the API server or Kubelet API — externally reachable without credentials. |
| Shortest Path from Identity to Full Cluster Compromise | `MATCH p=shortestPath((n:CH_Identity)-[*1..10]->(c:CH_Cluster)) RETURN p` | Finds the shortest path from any identity to the Cluster node, useful for prioritising remediation. |
| Identities that Can Bind Roles | `MATCH p=(n:CH_Identity)-[:CH_canBind]->(t:CH) RETURN p` | Identifies identities with the ability to create or modify RoleBindings or ClusterRoleBindings. |
| Identities that Can Escalate Roles | `MATCH p=(n:CH_Identity)-[:CH_canEscalate]->(t:CH) RETURN p` | Identifies identities with the `escalate` verb, allowing creation of roles with permissions beyond their own. |
| Identities Holding Both canBind and canEscalate | `MATCH p=(n:CH)-[:CH_canBind]->(r:CH)<-[:CH_canEscalate]-(n) RETURN p` | Identities with both edges to the same scope can create an elevated role and bind it to themselves, bypassing Kubernetes role binding restrictions. |
| Identities that Can Create Service Account Tokens | `MATCH p=(n:CH_Identity)-[:CH_canCreateToken]->(t:CH) RETURN p` | Identifies identities with the ability to mint tokens for ServiceAccounts via the TokenRequest API. |
| Identities that Can Impersonate | `MATCH p=(n:CH_Identity)-[:CH_canImpersonate]->(t:CH) RETURN p` | Identifies identities with `impersonate` permissions, allowing API requests to be made as other users, groups, or service accounts. |
| Privileged Pods | `MATCH p=(pod:CH_Pod)-[:CH_podPrivileged]->(n:CH) RETURN p` | Identifies Pods running with `privileged: true`, providing a direct path to the underlying Node on container compromise. |
| Host Namespace Pods | `MATCH p=(pod:CH_Pod)-[r:CH_podHostPID\|CH_podHostNetwork\|CH_podHostIPC]->(n:CH) RETURN p` | Identifies Pods sharing host PID, network, or IPC namespaces with the underlying Node. |
| Shortest Paths from Pod to Critical Permissions | `MATCH p=(pod:CH_Pod)-[:CH_compromiseServiceAccount]->(i:CH_Identity)-[r:CH_fullAccess\|CH_nodesProxyRCE\|CH_canBind\|CH_canEscalate\|CH_canExec\|CH_canCreateWorkload\|CH_canPatch\|CH_canCreateEphemeral\|CH_canImpersonate\|CH_canCreateToken\|CH_secretsRead]->(t:CH) RETURN p` | Chains `compromiseServiceAccount` with high-value RBAC edges to identify Pods whose service accounts hold critical permissions. |
| Pods Reaching IMDS | `MATCH p=(pod:CH_Pod)-[:CH_accessIMDS]->(imds:CH_IMDSService) RETURN p` | Identifies Pods that can potentially reach the cloud provider instance metadata endpoint. |
| Identities that Can Exec into Pods | `MATCH p=(n:CH_Identity)-[:CH_canExec]->(t:CH) RETURN p` | Identifies identities with `pods/exec` permission enabling direct command execution in running containers. |
| Identities that Can Create Pods | `MATCH p=(n:CH_Identity)-[e:CH_canCreateWorkload]->(t:CH) WHERE e.resource CONTAINS 'Pod' RETURN p` | Identifies identities with Pod create permissions, enabling deployment of arbitrary pod specs directly. |
| Identities that Can Create Workloads | `MATCH p=(n:CH_Identity)-[e:CH_canCreateWorkload]->(t:CH) WHERE any(k IN ['Deployment','StatefulSet','DaemonSet','ReplicaSet','ReplicationController','Job','CronJob'] WHERE e.resource CONTAINS k) RETURN p` | Identifies identities that can create workload controllers (Deployment, StatefulSet, DaemonSet, etc.). |
| Identities that Can Patch Pods | `MATCH p=(n:CH_Identity)-[e:CH_canPatch]->(t:CH) WHERE e.resource CONTAINS 'Pod' RETURN p` | Identifies identities with `patch` or `update` permissions on Pods, enabling image replacement or spec modification. |
| Identities that Can Patch Workloads | `MATCH p=(n:CH_Identity)-[e:CH_canPatch]->(t:CH) WHERE any(k IN ['Deployment','StatefulSet','DaemonSet','ReplicaSet','ReplicationController','Job','CronJob'] WHERE e.resource CONTAINS k) RETURN p` | Identifies identities that can patch workload controllers, triggering rolling updates that propagate modified pod templates across all replicas. |
| Identities that Can Read Secrets | `MATCH p=(n:CH_Identity)-[:CH_secretsRead]->(t:CH) RETURN p` | Identifies identities with `get` or `list` permissions on secrets, scoped to specific secrets, a namespace, or cluster-wide. |
| Identities that Can Create Secrets | `MATCH p=(n:CH_Identity)-[:CH_secretsCreate]->(t:CH) RETURN p` | Identifies identities with `create` permission on secrets, scoped to a namespace or cluster-wide. Enables planting a `kubernetes.io/service-account-token` Secret so the token controller mints a long-lived token for any ServiceAccount in scope. |
| Identities that Can Port Forward | `MATCH p=(n:CH_Identity)-[:CH_canPortForward]->(t:CH) RETURN p` | Identifies identities with `pods/portforward` permission, enabling tunnelling into Pod network stacks for lateral movement. |
| All Entry Points | `MATCH p=(svc:CH_Service)-[:CH_entryPoint]->(pod:CH_Pod) RETURN p` | Surfaces Services whose selectors match running Pods, representing potential external or internal access paths into the cluster. |
| Full Attack Chain - Entry Point to Critical Permissions | `MATCH p=(svc:CH_Service)-[:CH_entryPoint]->(pod:CH_Pod)-[:CH_compromiseServiceAccount]->(i:CH_Identity)-[r:CH_fullAccess\|CH_nodesProxyRCE\|CH_canBind\|CH_canEscalate\|CH_canExec\|CH_canCreateWorkload\|CH_canPatch\|CH_canCreateEphemeral\|CH_canImpersonate\|CH_canCreateToken\|CH_secretsRead]->(t:CH) RETURN p` | Chains entry points through service account compromise to critical RBAC permissions in a single query, showing complete attack paths from network access to cluster impact. |
| Pods with Write Volume Mounts | `MATCH p=(pod:CH_Pod)-[:CH_hasWriteVolume]->(v:CH_Volume) RETURN p` | Identifies Pods with writable volume mounts, potentially allowing modification of sensitive data, configuration, or binaries. |
| Pods with Read Volume Mounts | `MATCH p=(pod:CH_Pod)-[:CH_hasReadVolume]->(v:CH_Volume) RETURN p` | Identifies Pods with read-capable volume mounts, potentially exposing sensitive data within the container filesystem. |
| All Edges from a Namespace | `MATCH p=(src:CH)-[r]->(tgt:CH) WHERE src.namespace = 'namespace' RETURN p` | Returns all outbound edges from nodes in a specific namespace. Replace `namespace` with the target namespace in lowercase. |
| Cross-Namespace and Cluster-Wide Edges from a Namespace | `MATCH p=(src:CH)-[r]->(tgt:CH) WHERE src.namespace = 'namespace' AND (tgt.namespace IS NULL OR tgt.namespace = '' OR tgt.namespace <> 'namespace') RETURN p` | Surfaces edges that originate within a namespace but reach outside it — into a different namespace or cluster-wide resources. Useful for assessing namespace isolation. Replace both `namespace` placeholders with the target namespace in lowercase. |
| Pods in Namespace via Service Accounts to All Permissions | `MATCH p=(pod:CH_Pod {namespace: 'namespace'})-[:CH_compromiseServiceAccount]->(i:CH_Identity)-[r]->(t:CH) RETURN p` | Chains pod compromise through mounted service accounts to all outbound permissions for pods in a given namespace. Replace `namespace` with the target namespace in lowercase. |
| Token Creation Pivot to Privileged Identities | `MATCH (attacker:CH_Identity)-[:CH_canCreateToken]->(ns:CH_Namespace) MATCH (sa:CH_Identity)-[r]->(t:CH) WHERE sa.namespace = toLower(ns.name) RETURN attacker, ns, sa, r, t` | On-demand surfacing of the token-creation pivot: an identity that can mint tokens for a namespace can act as any ServiceAccount in it. Shows those SAs and all their outbound permissions without adding permanent edges to the graph. The attacker→namespace edge and the SA→permission edges are joined on the namespace property, so the result is a set of related nodes rather than a single connected path. |
| Impersonation Pivot to Privileged Identities | `MATCH (attacker:CH_Identity)-[:CH_canImpersonate]->(ns:CH_Namespace) MATCH (sa:CH_Identity)-[r]->(t:CH) WHERE sa.namespace = toLower(ns.name) RETURN attacker, ns, sa, r, t` | On-demand surfacing of the impersonation pivot: an identity with namespace-scoped impersonation can act as any ServiceAccount in that namespace. Shows those SAs and all their outbound permissions without adding permanent edges to the graph. |
